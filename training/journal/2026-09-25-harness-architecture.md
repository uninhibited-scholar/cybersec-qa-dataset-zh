# 架构决策：先稳定运行，再提升能力

日期：2026-09-25

本地私人模型的能力不能只用基座参数量或训练 loss 判断。推理外壳（Harness）负责上下文组织、路由、工具权限、记忆、格式约束、超时/回退和日志；这些组件会显著影响最终可用能力。Kimi Code 一类“模型 + 编排外壳”的架构值得作为设计参考。

## 约束

- 基础模型、网安 adapter、Harness、路由/回退层和自进化沙盒保持解耦。
- 先证明服务稳定：启动、健康检查、超时、回退、重启恢复和日志可追溯。
- 不因外壳增强而虚构工具能力、来源或执行结果。
- 候选 adapter 只能在隔离环境训练和评测；未经独立盲测及人工确认不得替换生产版本。
- 不修改既定评测题库、评分标准或生产工具权限。

## 下一阶段顺序

1. 固化基座/adapter/chat template/推理参数的版本清单和哈希。
2. 对 Harness 做无模型变更的稳定性测试：健康探针、请求超时、GPU 排队时的 CPU 小模型回退、结构化输出校验、错误可观测性。
3. 用固定题库分别比较裸模型、adapter 和完整 Harness；把“外壳收益”和“权重收益”分开报告。
4. 只有稳定性与回归闸门通过后，才在隔离沙盒继续候选训练和自进化实验。
