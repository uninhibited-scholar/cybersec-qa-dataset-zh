# Phase108 exposed scale/termination diagnostic — plan and results

## Purpose and interpretation boundary

This is a metadata-only investigation of the already exposed/rejected v0.9
16-case sample. It is intended to distinguish immediate EOS from long or
length-capped generation in the isolated HF adapter path. It is not blind,
scored, a capability comparison, an inference-scale selection, or a promotion
gate. It must not be combined with the frozen blind suite or used to change
its protocol after observing sealed outputs.

The grid contains a scale-zero base control and the Phase91 parent and
corrected-r2 candidate at scales 2.5, 5, 10, and 20. All arms use the same
dequantized base, greedy endpoint, no tools, exposed case selection, and
700-token cap. Per-case artifacts contain only case ID, response hash,
character count, empty flag, finish reason, and blinded=false metadata. The
summary reports aggregate counts and hashes; neither prompts nor response
text are persisted by the client. All run files are under a unique mode-0700
cluster directory with mode-0600 files. No training, weight write, API, or
rubric/protocol change is part of this diagnostic.
