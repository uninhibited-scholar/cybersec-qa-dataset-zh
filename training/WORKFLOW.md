# 持续目标工作协议

本项目按持续目标模式推进。用户给出总体目标并授权环境后，执行代理默认自主完成一个阶段闭环，不把中间步骤拆成逐项确认。

## 每个阶段的闭环

1. 读取当前仓库、远端主机、训练进程、模型路由和最近日志，确认事实状态。
2. 在独立目录准备数据、配置和候选适配器；基础模型、生产适配器与 Harness 保持解耦。
3. 启动训练或修复任务，用持久化进程运行，定期检查进度、损失、内存、NaN、崩溃和检查点。
4. 任务结束后运行独立盲测和回归测试；不得用训练损失单独判定成功。
5. 比较候选版本与当前版本，记录通过项、失败项、回归项和不确定项。
6. 未通过闸门的候选保留但隔离，绝不自动切换生产；只有全部必要闸门通过才提出部署。
7. 将配置、脚本、指标、日志摘要、决策和 Git 提交号写入 journal，运行 `git diff --check` 并提交。

## 默认安全闸门

- 指令遵循：普通回答、单词、JSON、拒答等格式均按要求输出。
- 证据边界：无来源时不虚构 CVE、KB、工具回执、联网查询、仓库审计或当前环境结论。
- 普通知识可回答：证据约束只用于需要外部事实或当前环境的主张，不能把所有问题都变成拒答。
- 工具真实性：只声明实际连接且有回执的工具；候选模型不能自行扩大权限。
- 盲测隔离：测试集不参与训练；候选之间独立加载；生产 API 不作为实验沙盒。
- 可回滚：保留旧适配器、检查点、配置和启动方式，任何切换前先验证回滚路径。

## 自进化研究边界

循环自进化只在离线、可溯源、可回滚沙盒中进行。模型可以提出数据、策略或适配器候选，但不能自行批准上线、修改评测器、扩大工具权限或删除历史证据。候选必须经过独立评估器和人工/外部闸门批准。

## 汇报方式

阶段进行中只报告有意义的状态变化；完成时给出训练指标、盲测结果、部署决定、失败原因、Git 提交号和下一阶段动作。若观察超时，重新检查同一进程或任务句柄，不因暂时看不到输出而重启任务。
